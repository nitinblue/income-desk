## Errors & Blockers

### P0: Network Policy Blocks All Market Data

- **Error:** `HTTP Error 403: Host not in allowlist` on every yfinance call
- **Scope:** All 21 India tickers + all US benchmark tickers (SPY, TLT, EEM, ^VIX, etc.)
- **Impact:** Entire data pipeline dead — scan, regime, rank, technicals all fail
- **Root cause:** Cloud execution environment restricts outbound HTTP to non-allowlisted hosts. yfinance's data source is blocked.
- **Fix needed:** Either add yfinance data hosts to the network allowlist, or use a data provider that is already allowlisted (e.g., Alpaca, Dhan's own API for India data)

### P1: SimulatedAccount Missing `get_positions`

- **Error:** `'SimulatedAccount' object has no attribute 'get_positions'`
- **Location:** Step 4 (Monitor Positions) in `trader.py`
- **Impact:** Position monitoring silently falls back to "no positions" — masks the bug in normal runs
- **Fix needed:** Add `get_positions()` stub to `SimulatedAccount`, returning `[]`

### P2: Dhan Broker Not Connected

- **Error:** `Dhan credentials required. Set DHAN_CLIENT_ID + DHAN_TOKEN or add to ~/.income_desk/broker.yaml`
- **Impact:** Live data, live positions, and real order routing unavailable
- **Note:** Expected in this automated environment — Dhan credentials are not provisioned in the cloud runner

## Assessment: Is the Platform Stable?

**No. The platform is not stable for production use in this environment.**

### What's working
- Harness infrastructure launches and completes without crash
- Market context produces a usable macro view (risk-on, size factor, macro events)
- Regime map is rendered correctly (R0 is the honest answer when data is unavailable)
- Simulation mode correctly gates on "no data" rather than fabricating prices

### What's broken
1. **Data pipeline is 100% blocked** by the cloud network policy (HTTP 403). This is the single largest blocker — without real OHLCV, nothing downstream works: no regime, no scan, no rank.
2. **SimulatedAccount.get_positions** is missing — a code defect that breaks position monitoring in every simulated run.
3. **Scan → Rank not wired** (FB-009): even if data were available, scan results are not passed to rank, so the full pipeline would still not close.
4. **35 stale items** with zero fresh — project momentum is stalled; none of the known bugs are being closed between sessions.

### What's needed for India go-live (3 remaining blockers at 70%)
1. Resolve the network allowlist issue (or switch to an allowlisted data provider for the cloud runner)
2. Wire Dhan credentials in the environment (DHAN_CLIENT_ID + DHAN_TOKEN)
3. Fix SimulatedAccount.get_positions and the Scan → Rank pipeline wiring

The macro context and regime framework are sound. Once data flows through, the 70% India readiness score should translate to functional end-to-end runs.
