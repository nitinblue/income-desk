## Errors & Blockers

### Critical (blocks all trading)

1. **yfinance proxy blocked** — All market data fetches fail with `curl: (7) CONNECT tunnel failed, response 403`. This is an environment-level blocker: the scheduled agent container cannot reach `fc.yahoo.com` or `query1.finance.yahoo.com` through the HTTPS proxy. **No regime detection, no scan, no ranking is possible.** This needs proxy allowlisting or an alternative data path (cached historical data, Dhan/TastyTrade quotes).

2. **TastyTrade broker auth failed** — No `TASTYTRADE_*` credentials in the scheduled agent environment. Simulated account lacks `get_positions()` method (BUG).

3. **pydantic_core ABI mismatch** — The installed `pydantic_core` `.so` was compiled for Python 3.13 but the system default `python` is 3.11. Required workaround: use `python3.12`. This is a fragile dependency state that will break silently if the runner changes Python versions.

## Assessment: Platform Stability

**Platform is NOT stable for production trading.**

Root cause: The scheduled agent environment blocks outbound HTTPS to Yahoo Finance (proxy 403). Without market data:
- Regime detection returns R0/Unknown for all tickers
- Scan passes 0 candidates
- No trade recommendations are generated
- The harness runs but produces no actionable output

This is not a code bug — the trader logic executed correctly and degraded gracefully (simulated mode, no crash). But the daily report cycle has zero trading value until the data connectivity issue is resolved.

**Secondary blocker:** Broker auth not available in this environment. Even with data restored, live quotes and position management require TastyTrade credentials injected as environment variables.

**Recommendation:** 
1. Investigate proxy allowlist for `*.yahoo.com` / `query1.finance.yahoo.com`
2. Add `TASTYTRADE_USERNAME` / `TASTYTRADE_PASSWORD` to the scheduled agent environment
3. Fix `SimulatedAccount.get_positions()` AttributeError (minor)
4. Address FB-009 (scan → rank pipeline wiring) once data is available
